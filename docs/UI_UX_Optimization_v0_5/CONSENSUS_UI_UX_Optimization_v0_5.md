# 共识阶段: UI_UX_Optimization_v0_5

## 1. 明确的需求描述和验收标准

*   **UI配色方案升级**:
    *   主色调更换为“马卡龙橘色”（Macaron Orange）。
    *   暗色模式（Dark Mode）需要重新设计，确保深色背景与橘色主调及文本对比度符合 WCAG 标准。
    *   亮色模式（Light Mode）要协调统一，避免界面在明亮光线下出现刺眼或对比度低的问题。
*   **黑夜模式下文本与元素修复**:
    *   修补所有遗漏的亮色组件、文本、图标。
    *   保证朋友圈文字在暗黑模式下清晰可见。
    *   对采用黑体字的地方进行调整优化，增强易读性。
    *   Agent专区的UI文本对比度优化。
*   **消息发送与接收机制**:
    *   修复自己发送消息后内容立刻消失的问题（乐观更新机制异常）。
    *   修复接收到对方回复时无法实时显示的问题（状态更新异常或组件未能及时重渲染）。
    *   实现消息收发无需刷新页面即可实时展示。
*   **朋友圈图片加载可靠性**:
    *   针对图片加载失败，提供可靠机制（采用备用图片服务代理、强化错误状态处理及添加加载中指示器）。
    *   不只是展示文字失败卡片，而应尽量让图片成功渲染。
*   **AI角色提示词与机制**:
    *   针对所有角色（包括“初音未来”）的提示词进行优化与风格统一。
    *   建立测试流程。
    *   实现AI**“选择性回复”**机制，打破“句句回复”的机械感，使其更像真人。
    *   去除原有与Agent心情、好感度相关的展示，强化工具属性。
*   **动效与状态展示**:
    *   修正消息气泡夸张弹出的动效，使其更加自然柔和。
    *   增加AI服务状态展示（已读、未读、对方正在输入中等实时响应状态）。
*   **流式传输支持 (Streaming)**:
    *   为Agent回复实现流式文字输出（类似于ChatGPT的逐字展示效果），明显改善用户的等待体验。
    *   从视觉上清晰区分“聊天界面”和“工具界面”。

## 2. 技术实现方案和约束

*   **样式重构**: 直接修改 `src/index.css`，定义 `--color-primary` 系列为马卡龙橘色体系，修改暗色与亮色的变量映射，检查所有 Tailwind 类，去除非法硬编码的色值。
*   **状态管理与持久化**: 分析并重写 `src/core/chat/ChatEngine.js` 中的消息派发事件，使得 React 的 Context 或 Hooks (`useChatService`) 能够精准订阅状态，保障消息实时不刷新更新。
*   **流式架构**: 修改 `AIPipeline.js` 以及 `APIClient`，采用 `fetch` 结合 `ReadableStream` 或者 `EventSource`，实现逐字流渲染。
*   **代码隔离**: 保证前端逻辑的纯粹性，API Key 继续置于 `.env`。
*   **兼容性约束**: 继续沿用现有基于 TailwindCSS 和 React Hooks 的生态架构，尽量不引入新的重量级依赖包，以轻量组件为主。

## 3. 任务边界限制

*   所有的 AI 模型请求均建立在当前的 APIClient 之上（如 OpenAI 兼容接口，或者 MiniMax 接口），仅针对网络层和流式协议进行前端改造，不涉及自建后端服务。
*   图片代理部分，通过前端构造 url 进行跨域中转处理，不编写后端代理服务。

## 4. 所有不确定性已解决
*   流式支持将在 API 层进行判断与降级处理（如 API 支持 stream=true 则采用，否则沿用普通 fetch 模拟打字机）。
*   UI 色彩由本智能体通过设计专业知识自动调优出最优“马卡龙橘色”调色板。
