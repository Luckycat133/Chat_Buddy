# 对齐阶段: UI_UX_Optimization_v0_5

## 1. 项目与任务规范
*   **项目架构**: Chat_Buddy 采用分层架构（展示层、应用层、领域层、基础设施层），基于 React 和 TailwindCSS 开发。
*   **现有样式体系**: 在 `src/index.css` 中定义了完整的现代变量系统，目前采用 OLED Dark, Premium, Sleek, Glassmorphism 理念，主色调为 Premium Gold Accent (`#CA8A04`)。
*   **任务目标**: 对 UI/UX 进行全面深度优化，解决黑夜模式对比度、朋友圈图片加载、文本显示、聊天消息展示（如刚发消息消失）、Agent 提示词与动效调整、AI 服务状态展示、AI 智能选择性回复以及系统整体配色重构（马卡龙橘色为主色调）。

## 2. 原始需求分析
1.  **黑夜模式全面检查**: 解决无意遗漏的亮色组件、文本、图标、背景的对比度问题，确保可读性（WCAG）。
2.  **朋友圈图片加载失败**: 排查网络请求、路径、服务器响应及客户端缓存（不仅仅是前端渲染时的文字 fallback），实现可靠加载与错误处理。
3.  **文本显示优化**: 朋友圈文字看不清问题、黑体字可读性、Agent 专区文本对比度。
4.  **聊天界面消息问题**: 发送后立即消失、对方回复不实时、需要刷新等渲染机制与稳定性问题。
5.  **Agent 提示词优化**: 调整“初音未来”等提示词符合设定，优化所有角色设定，建立测试机制与借鉴机制。
6.  **动效优化**: 降低气泡弹出的夸张度，统一全应用动效适度性，建立设计规范。
7.  **AI 服务状态指示**: 添加已读/未读、处理中状态，实时准确。
8.  **AI 回复机制优化**: 实现“选择性回复”，增强自然度，根据上下文决定是否回复。
9.  **全面优化 UI 配色方案**: 解决目前配色诡异，**以马卡龙橘色为主色调**，设计亮色和暗色两套统系，符合现代美学。
10. **Agent 功能和界面调整**: 移除好感度和心情功能，强化工具属性，实现流式传输，区分聊天和工具界面的视觉风格。

## 3. 需求理解与智能决策 (智能决策策略执行)
*   **关于配色重构 (马卡龙橘色)**: 当前项目刚从早期的设计升级到 OLED Dark 风格。需求明确要求“以马卡龙橘色为主色调”，因此需要重写 `src/index.css` 中的 `var(--color-primary)` 系列变量，并对应调整相关的 hover/active 及渐变色彩。同时需要设计一套协调的亮色和暗色（Dark Mode）逻辑。
    *   *智能决策*: 将采用 `hsl(28, 90%, 65%)` 左右的马卡龙橘色作为 Primary Color，搭配深褐/暖灰作为暗黑模式背景，以保持“Premium”的同时符合需求。
*   **关于图片加载失败**: 当前代码 `MomentMediaGrid.jsx` 中，只有简单的 `onError` 重试机制和文字 fallback（`ImageFallbackCard`）。真正导致加载失败的原因可能在于图片来源（如 Unsplash API 限制、防盗链、跨域等）。
    *   *智能决策*: 我将实现一个更加健壮的防盗链图片代理或使用更可靠的图片代理库（如 `images.weserv.nl` 缓存代理），并在 UI 上加入骨架屏加载状态，而不仅仅是 fallback 卡片。
*   **关于消息发送立刻消失/不实时**: 核心问题在于 `ChatEngine` 状态更新机制与 React 组件重渲染不同步，或乐观更新（Optimistic UI）逻辑有缺陷。
    *   *智能决策*: 需要检查 `useChatService` 或 `ChatEngine` 的持久化与订阅回调机制，确保发送后立即将本地构建的消息对象推入视图列表，收到 AI 响应时再原地更新状态（而不是刷新列表）。
*   **AI 选择性回复机制**: 目前 AIPipeline 可能被直接触发。需要一个判别层。
    *   *智能决策*: 在消息入口处增加判定规则（比如：如果连续几句是用户的短语聊天，按概率或是否包含特定疑问词决定是否调用 AI API）。
*   **关于移除好感度/心情**: 需从 `ChatEngine` 数据模型和 UI 组件中剔除相关逻辑。
*   **状态指示**: 需利用现有的 `ChatEngine` 状态事件，向 UI 发送 `isTyping` 或 `isRead`。

## 4. 边界确认与疑问澄清
*   **边界限制**: 仅在客户端层面（React + 本地引擎）进行优化，不需要后端持久化数据库改造（现有基于 localStorage 的存储）。
*   **疑问**: AI 流式传输 (Stream) 目前是否在底层 `AIPipeline.js` 已经有长链接支持？
    *   *决策回答*: 如果没有，我将需要在 `APIClient` 和 `AIPipeline` 中封装 Fetch API 的 ReadableStream 处理。
